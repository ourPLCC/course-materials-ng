    Language V4

    So far our languages do not allow for anything like repetition. In an expression-based language (ours fall into this category), repetition is typically accomplished by recursion, and recursion depends on the ability to apply function recursively. So we need the ability to define and to call functions.

    As a starting example, consider the following V4 program.

    let
  f = proc(x) +(x, 3)
in
  .f(5)

    Using V4's specification, this program evaluates to 8.

    A quick tour

    The declaration in the let expression defines a function using the proc keyword and assigns it a name (i.e., f). The let body applies the function using the dot character (.) with a single parameter (i.e., 5).

    Functions

    Think of a function as a "black box" that, when given zero or more input parameters, returns a single result value. The number of parameters that a function accepts is called its arity.

    To define a function means to describe how it behaves. To apply a function means to give the function the proper number of parameters and to receive its result. Formal parameters refer to the list of parameters appearing in a function definition. Actual parameters refer to the list of parameters appearing in a function application.

    Using mathematical notation, we can define a function \(f\) by

    \[ f(x) = x + 3 \]

    and we can apply the function \(f\) by

    \[ f(5) \]

    The result of this particular application is \(8\).

    ProcVal

    In Language V4, functions are treated as values just like integers. In particular, we create a ProcVal class that extends the Val class. This implies that a ProcVal object can occur anywhere a Val object is expected.

    Observations

    It is possible to define and to apply a function in one expression, such as

    .proc(x) +(x, 3) (5)

    The evaluation of both this expression and the program defined at the beginning of this chapter return the same value, namely the integer 8.

    Notice, too, that proc(x) +(x, 3) also returns a value, but the value is a function, not an integer. (One’s intent when defining a function is eventually to apply it, although this is not a requirement.)

    Examples

    Below are several V4 programs using functions.

    The following program

    let
  f = proc(x, y) +(x, y)
in
  .f(3, 8)

    evaluates to 11.

    The second program

    let
  f = proc(z, y) +(10, y)
in
  .f(3, 8)

    returns 18.

    Finally, this program

    let
  x = 10
in
  let
    x = 7
    f = proc(y) +(x, y)
  in
    .f(8)

    also returns 18.

    In this third example, name x in the proc definition refers to the enclosing x (which is bound to 10), not to the inner name x (which is bound to 7). Remember the rules for evaluating the declarations in let expression!

    Now consider the next three examples, all of which evaluate to 5:

    let
  app = proc(f, x) .f(x)
  add2 = proc(y) add1(add1(y))
in
  .app(add2, 3)

    let
  app = proc(f,x) .f(x)
in
  .app(proc(y) add1(add1(y)), 3)

    .proc(f, x) .f(x) (proc(y) add1(add1(y)), 3)

    In the first of these three examples, observe that we can pass a function (in this case add2) as a parameter to another function. This app function takes two parameters and returns the result of applying the first actual parameter to the second. Of course, the first parameter had better be bound to a function for this to work. (If it is not, an attempt to apply it throws an exception.)

    In the second example, we have eliminated the identifier add2 and instead simply replaced add2 in the application .app(add2, 3) with the nameless function proc(y) add1(add1(y)) that used to be called add2.

    In the third example, we have even eliminated the name app.

    Finally consider the following example, which evaluates to 120:

    let
  fact = proc(f, x)
    if x
    then *(x, .f(f, sub1(x)))
    else 1
in
  .fact(fact, 5)

    This example, quite a bit more subtle than the previous ones, shows how you can achieve recursion — factorial, in this case — using our simple language (which does not yet support direct recursion!).

    Syntax

    We are now prepared to add syntax and semantics to support functions. First we add grammar rules for function definition and application, and display their corresponding abstract syntax classes:

    <Exp:ProcExp>    ::= <Proc>
def __init__(self, proc)
<Proc>           ::= PROC LPAREN <Formals> RPAREN <Exp>
def __init__(self, formals, exp)
<Formals>        **= <SYMBOL> +COMMA
def __init__(self, symbolList)
<Exp:AppExp>     ::= DOT <Exp> LPAREN <Rands> RPAREN
def __init__(self, exp, rands)

    Obviously, appropriate definitions of PROC and DOT tokens must accompany these rules.

    ProcVal

    Before we can go any further, we need to tackle the definition of a ProcVal, which is what we should get when we evaluate a ProcExp expression.

    A ProcVal object must capture the formal parameters as an instance of the Formals class, and it must remember its function body as an instance of Exp. But what environment should we use to evaluate the function body when the function is applied? To conform to our notion of static scope rules, we want to evaluate the function body using the environment in which the function is defined. So any variables in the function body which are not among the formal parameters – in other words, the variables that occur free in the function body – are bound to their values in the environment in which the function is defined.

    In programming languages terminology, the term closure refers to an entity that captures all of the ingredients necessary to apply a function. In Language V4 ProcVal objects are closures.

    The attributes of the ProcVal class appear here:

    class ProcVal(Val):

    def __init__(self, formals, body, env):
        self.formals = formals
        self.body = body
        self.env = env

    Recall that we can do two things with a function: define it and apply it. We will discuss function definition shortly, but first we give the semantics of function application.

    Function application

    The method eval in the AppExp class defines the semantics of function application.

    AppExp
%%%
def eval(self, env):
    v = self.exp.eval(env)
    args = self.rands.evalRands(env)
    return v.apply(args, env)

    Here are a description of these steps:

    1. Evaluate exp in the current environment; this evaluation must return a ProcVal object (a closure) with attributes consisting of the list o formals parameter, the function body, and the captured environment.
    2. Evaluate rands (the actual parameter expressions) in the current environment to get a list of Vals (the parameters). [Note: we did exactly the same thing when evaluating the rands of a PrimappExp.]
    3. Evaluate the body of the function with the current environment and actual arguments computed in the previous step.

    The only thing we have left is to implement the behavior of the apply method in the Val class. Since we want apply only to be meaningful for a ProcVal object, we define a default behavior in the (abstract) Val class to throw an exception for anything but a ProcVal:

    class Val:

    # Some Vals can be applied to a list of arguments (e.g. a ProcVal).
    # Like the evaluation of an expression, the application of a Val takes
    # place in the context of an environment, which arrives as the second
    # parameter. An applied Val may use or ignore that environment as its
    # own semantics require.
    def apply(self, args, env):
        raise LanguageError(f"Cannot apply {self}")

    For a ProcVal, here is the implementation of apply:

    class ProcVal(Val):
    def apply(self, args, env):
        if len(self.formals.symbolList) != len(args):
            raise LanguageError("formals/args number mismatch")
        bindings = Bindings(self.formals.symbolList, args)
        nenv = self.env.extendEnv(bindings)
        return self.body.eval(nenv)

    These steps are as follows:

    1. Check that the number of actual parameters matches the number of formal parameters. If there is mismatch, throw an exception.
    2. Create bindings of the function’s list of formal parameters (formals) to the list of actual parameters passed as an argument (args).
    3. Use these bindings to extend the environment (env) captured by the function.
    4. Evaluate the body of the function in the (extended) environment (nenv).

    Function definition

    Let us now examine the detailed semantics of a ProcExp, which is used to define a function.

    As noted earlier, a ProcVal closure is constructed with instance attributes consisting of the list of formal parameters (a Formals object), the function body (an Exp object), and the environment in which the function is defined (an Env object).

    The makeClosure method in the Proc class creates a ProcVal object given an environment:

    Proc
%%%
def makeClosure(self, env):
    return ProcVal(self.formals, self.exp, env)
%%%

    The semantics of the eval method in the ProcExp class is now trivial:

    ProcExp
%%%
def eval(self, env):
    return self.proc.makeClosure(env)
%%%
